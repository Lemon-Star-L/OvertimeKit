# 加班数据核对工作台｜OvertimeKit

按员工编码归集四类加班时数，核对加班明细与考勤汇总，支持异常筛选、逐项及批量确认、浏览器缓存和 Excel 导出。数据在本地浏览器处理，不上传服务器，不修改输入文件。

**版本：1.0.0** · 作者：YiLong Li

[中文操作手册](help/操作手册.md)

## 主要功能

| 模块 | 能力 |
| --- | --- |
| 导入与预览 | 双 Excel 导入、工作表选择、表头识别、字段映射及分页预览 |
| 加班核对 | 累计调休、工作日、休息日及法定节假日加班，检查时数差异及未匹配员工 |
| 异常列表 | 每页 20 项，按状态、编号、员工编码、Excel 行号、字段、原因、原值、计算值筛选 |
| 批量处理 | 勾选单项或全选当前页，批量保留原值、确认已核查、采用计算值或输入统一人工时数 |
| 结果导出 | 已确认项按处理意见更新；未核对完时经提示确认后导出，未确认项保留原值 |
| 进度与缓存 | 自动缓存工作簿、配置与确认记录；支持进度 JSON 下载和恢复 |
| 操作反馈 | 处理状态、结果提示、异常提示，以及工作区和浏览器缓存清理 |

## 快速开始

直接使用 Chrome 或 Edge 打开 `output/加班数据核对工作台.html`，无需启动后台服务。修改资源后，在项目根目录重新构建：

```bash
python main.py
python main.py --no-browser
python main.py --output D:/OvertimeKit_Output
```

Python 3.9+，仅使用标准库，也可执行 `uv run main.py`。

## 使用流程

1. 导入基础数据表和汇总表，确认工作表、表头及字段映射。
2. 执行匹配，在异常列表中筛选并查看待处理项目。
3. 逐项处理，或勾选当前页项目后批量处理；处理说明选填。
4. 导出核对结果。未全部核对时需确认提示，文件会标明未完成状态。
5. 查看底部缓存状态，必要时下载进度 JSON 备份。

## 匹配口径

| 补偿方式 | 加班类型 | 汇总字段 |
| --- | --- | --- |
| 调休 | 不限 | 加班用于调休 |
| 加班费 | 工作日加班 | 加点时数 |
| 加班费 | 休息日加班 | 周末加班时数 |
| 加班费 | 法定节假日加班 | 节假日加班时数 |

同员工有效明细全部累计，不自动去重，也不按月份或审批状态过滤。编码按文本匹配；源文件已丢失的前导零和精度无法恢复。Excel 公式读取保存的缓存值，不重新计算。无效明细不计入汇总，并列为异常。

## 缓存与清理

数据、配置、匹配结果和已确认记录自动写入本工具的 IndexedDB。下次使用同一浏览器、同一 HTML 路径打开时尝试恢复。底部显示实际缓存保存或失败状态；缓存不是永久备份，建议保留源 Excel 和进度 JSON。

- 清空工作区：清除当前数据和确认记录，并保存空工作区。
- 清空浏览器缓存：仅删除本工具的已保存快照，当前页面数据保留；下一次数据操作会重新缓存。

移动 HTML、无痕模式、浏览器权限、存储配额或清理浏览器数据可能影响恢复。切勿同时在多个标签页编辑同一工作区，缓存以最后一次写入为准。

## 输出说明

结果文件包含核对结果、核对记录、基础数据汇总、未匹配员工和导出说明。未确认项在核对记录中保留“待确认”标记。未全部核对的文件名含“未全部核对”，并记录待确认数量。

导出为值表，不保留原样式、公式、宏和其他 Sheet。第三方许可见 `assets/SheetJS-LICENSE.txt`。


## 按异常原因及字段批量处理

“异常原因”和“字段”提供下拉选项，按本次匹配结果自动生成，选择后精确筛选。其他列继续支持文本包含匹配，多项条件同时生效。

1. 选择异常原因，例如“基础数据无此员工记录”，必要时再选择目标字段。
2. 批处理范围选择“当前页勾选项”，或“全部筛选结果（跨页）”。
3. 选择处理方式，点击执行，核对弹窗中的范围、原因、字段和数量后确认。

“全部筛选结果”遵循状态、搜索及所有字段条件，不受当前页限制；“当前页勾选项”仅处理勾选行。不适用所选处理方式时，整批不执行。默认使用当前页勾选项。


## 表头筛选与时数对比

筛选控件直接位于异常列表的对应表头内；异常原因、字段使用下拉选项，其他列使用文本包含匹配。即使没有符合条件的结果，表头筛选仍保留，可继续修改或重置。

列表和详情卡片展示“汇总表现有值（小时）”“基础表计算值（小时）”及“差值（计算－现有）”。员工级异常按调休、加点、周末、节假日四类逐项展示；单个字段差异只展示对应时数。员工编码仅用于标识员工，不再作为时数原值。

- 基础表未找到该员工记录：四类按 0 汇总，不代表已确认没有加班，仍需核实是否漏导。
- 基础表有记录但没有有效时数：记录已因数值或分类问题排除，应检查无效明细。
- 基础表存在有效及无效记录：计算仅包含有效明细，详情显示总记录数及有效数。
- 重复员工编码、无法定位汇总行等情况不强行计算差值，显示“无法比较”。

核对记录导出同步采用以上对比口径。已确认后的最终值仍按所选处理方式生成；“现有值”始终指输入汇总表中的原始时数。
